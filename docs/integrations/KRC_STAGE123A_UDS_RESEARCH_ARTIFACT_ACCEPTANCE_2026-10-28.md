# KRC Stage123-A — isolated UDS + Research + Artifact acceptance (2026-10-28)

Scope: **KRC-owned staging only**. Production/public/MEDIA and K_Sentinel Stage114 v1 remain unchanged, FREE_ONLY.

Code: `src/krc_research/uds_stage123.py`; tests `tests/test_uds_stage123.py`, `tests/test_uds_real_science123.py`. Route: stdlib HTTP/1.1 over isolated Unix socket, SO_PEERCRED UID allowlist, `POST /v1/execute`, `GET /healthz`, `GET /v1/artifacts/{artifact_id}`. File fetch uses a request-id selector header `X-KRC-Request-ID` and checks principal + request ownership inside KRC Artifact Exchange; no public URL. A full UTF-8 JSON response over 1MiB is replaced with a small error, not emitted directly. Existing `ResearchBoundary120` handles ledger/idempotency and inline/artifact switching. Files are emitted in chunks; the underlying Stage117 reader uses hash pre-verification with an advisory read/cleanup lock. Four operation names are allowlisted by KRC. `ScienceAdapter122` connects to the actual signed scientific dispatch code, with bibliography external network disabled unless a test-safe function is explicitly supplied.

**Essential caveats / NO-GO:** UID->`K_Science` mapping in test config is STATIC and does not independently prove OIDC `principal`, `repository`, or `workflow_ref` from Sentinel; no authenticated transport assertion forwarding protocol. E2E through actual K_Sentinel NOT RUN. Operation-specific authorizer still needs stronger science ACL / user approval binding. The signed science-task replay registry inside `ScienceAdapter122` is only an in-memory set; Stage119 durable request_id ledger is separate. No proof of durable at-most-once scientific side effects after crash. Artifact files are only protected from cooperating processes via advisory locking; no immutable snapshot guarantee against untrusted mutators, and no tested client disconnect mid-stream. The first yielded chunk is preflighted before headers; later I/O errors cannot be converted to clean JSON once streaming starts. Response-size and 200-MiB stress acceptance not yet exhaustive. Full four-operation real UDS E2E not done: only real profile operation. The `GET` endpoint must NOT be exposed beyond isolated testing until these issues are resolved.
