# KRC prepared-request read contract v1 (2026-11-25)

Status: KRC SPECIFICATION COMPLETE / PARTNER REVIEW PENDING / DEFAULT DISABLED.
This is a normative implementation candidate, not a deployed API or owner

## 1. Routes and trust

External: GET /staging/v2/requests/<request_id>/prepared, no query or body,
exact ASCII RID KS-[0-9a-f]{32}. Existing Stage127 Tailnet and OIDC admission.
Internal: POST /v1/requests/prepared/read, over existing authenticated local
IPC architecture, separate purpose boundary. Reuse bounded UDS framing,
SO_PEERCRED and write-half-close; no new public listener. Sentinel must
derive identity from verified OIDC, not caller JSON. Initially only existing
K_Science principal, repository and main workflow identity admitted.
Retain existing exact workflow allowlist; verify actual workflow and run
identity at Sentinel before signing. No new trusted workflow by implication.
KRC checks configured Sentinel peer UID and exact trusted identity.
A separate root-provisioned 32-byte random HMAC key with key ID
stage135-prepared-read-v1, restricted to the existing two service identities;
no reuse of artifact.read or execution keys. Key custody and socket placement
must be reviewed against live service ownership before installation.

## 2. Exact internal JSON envelope

All fields required; no extras, duplicate keys, BOM, non-UTF8, NaN or Infinity.
No externally supplied filesystem path or authorization boolean.

```json
{
  "version": "krc-prepared-read/1",
  "operation": "prepared_request.read",
  "request_id": "KS-aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
  "identity": {
    "principal": "K_Science",
    "repository": "kolemasakar/K_Science",
    "workflow_ref": "refs/heads/main"
  },
  "auth": {
    "key_id": "stage135-prepared-read-v1",
    "issued_at_epoch": 1795636800,
    "nonce": "0123456789abcdef0123456789abcdef",
    "mac_sha256": "<64 lowercase hex characters>"
  }
}
```

Illustrative timestamp/nonce only. Version and operation literal and
domain-separated from result reads; key_id exact. Timestamp integer UTC
epoch seconds, no bool. Nonce 32 lowercase hex characters generated by
CSPRNG; MAC 64 lowercase hex. HMAC-SHA256 over UTF-8 JSON of whole envelope
excluding only auth.mac_sha256, sorted keys, compact separators, no ASCII
escaping, no non-finite values (same canonicalization as existing artifact
read). All fields are signed. Validate shape, trusted peer and identity,
key ID, timestamp and constant-time MAC before atomic nonce claim.
Accept absolute clock skew <=60 seconds. Durable nonce retention >=900
seconds; atomic unique tuple (key_id, principal, nonce), survives restart;
do not claim on invalid MAC. No fallback on registry failure. Internal
envelope <=4096 bytes. Reject ambiguous HTTP framing, require one
Content-Length, no Transfer-Encoding, exact EOF before dispatch.
5s idle / 20s absolute deadline / 4 concurrent workers initial limits.

## 3. Independent disclosure authorization

KRC owns a private registry binding RID, principal, repository, workflow_ref,
profile_sha256, body_sha256, size_bytes, internal immutable object reference,
issued_at, expires_at, status, decision_ref. No request-selected path.
Statuses PREPARED, AUTHORIZED, REVOKED; expiry derived from server clock.
PREPARED denies all delivery. Owner decision after joint acceptance explicitly
authorizes exact recipient and bytes; no caller-set status. Maximum initial
delivery authorization 900 seconds from approval, no automatic renewal.
Read may be repeated with a fresh signed nonce within authorized window,
provided execution grant is not RUNNING, COMPLETED, CANCELLED, EXPIRED or
otherwise terminal. A transport read does not approve, consume or extend
execution consent. Execution still requires separate existing APPROVED
state and exact profile, unchanged 86400-second maximum. Revocation or
expiry denies further reads; explicit owner decision required for renewal.
Read the immutable profile and compare its digest and exact canonical POST
body against stored descriptor and actual bytes; enforce 1..262144 bytes.
Use regular owner-only file, no symlinks, no arbitrary path, bounded spool,
check file stability and SHA256. Recheck disclosure and execution state at
final release boundary. Revocation after release cannot recall bytes.
Keep body out of logs; audit only decision ref, RID, identity, timestamp,
status, byte count and hash in restricted logs. No real data in public
repo, workflow input/output, cache or Actions artifacts.

## 4. Responses

Success external HTTP 200, Content-Type application/json, exact single
Content-Length, X-Content-SHA256 (lowercase hex), X-KRC-Request-ID,
Cache-Control no-store, X-Content-Type-Options nosniff, no redirects or
compression. Internal success application/octet-stream with exact length
and X-Content-SHA256, preserving bytes (existing spool convention).
Sentinel verifies internal length/hash before forwarding, consumer checks
pinned expected RID/length/hash from trusted KRC descriptor, not merely
self-reported response header. Do not parse/re-serialize prepared body.
Error JSON exactly {"error":"CODE"}, no path, payload, credentials or
exception text. External unauthenticated 401 UNAUTHORIZED; internal
wrong peer/MAC/identity, stale or replayed signature 403 FORBIDDEN.
Authenticated wrong scope, missing RID, unapproved or revoked grant:
uniform 403 FORBIDDEN (avoid existence oracle). Authorized scope expired:
410 GONE. Disabled route 404 NOT_FOUND; malformed 400 INVALID_REQUEST;
unsupported method 405 METHOD_NOT_ALLOWED; envelope or object limit 413
REQUEST_TOO_LARGE; internal media type 415 UNSUPPORTED_MEDIA_TYPE;
deadline 408 REQUEST_TIMEOUT; integrity or upstream framing mismatch
502 UPSTREAM_INVALID_RESPONSE; unavailable registry/backend or capacity
503 BACKEND_UNAVAILABLE. No success bytes on pre-release error; truncated
stream is failure at consumer, never a successful delivery.
