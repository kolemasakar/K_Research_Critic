# Stage131 — human consent provenance and grant issuance protocol
**STAGING ONLY / FREE_ONLY / Production NO-GO. Not an approval.**

## Independent approval source
The owner must explicitly authorize one *specific* scientific request outside the incoming Science/Sentinel JSON and independently of source-control commits. A request to develop Stage131 or to conduct synthetic tests is **not** consent to sign a specific scientific task or transmit unpublished corpus material. An approval ticket must be human-verifiable, narrow, time-limited, and retained as immutable evidence in a separately protected owner/operator audit. The running KRC service must have no issuance method.

## Mandatory ticket fields
- ticket_id, authorized_owner_id_reference, independently_verified_channel, exact original owner instruction reference and its digest;
- operator_id, operator_verified_at_utc, issuer_identity, issued_at_utc and ticket_audit_digest;
- consent_ref; request_id; task_id; operation (one of the four science operations); exact canonical principal K_Science;
- profile_ref and specific evidence_refs; SHA-256 of canonical science_payload; canonical context SHA-256;
- approved_at and expires_at UTC (strict bounded duration), decision=APPROVED, permitted data classification and optional allowed PUBLIC DOI list;
- KRC source SHA, workflow SHA, signing boundary SHA; rollback/revocation reference.
Never store secrets, bearer tokens, private unpublished text or raw human credentials in a ticket. Reject absent, conflicting or unverifiable evidence.

## Verification / issuance order
1. Independently authenticate owner instruction through an authorized non-payload channel. Ensure exact bytes of intended task/operation/profile/evidence/payload are presented to owner; log decision and ticket digest.
2. A separate accountable operator verifies ticket, approvals scope, time, classification and source version. A boolean user_profile_approved is insufficient. A GitHub comment does not itself attest human identity.
3. Only after verification, a privileged operator may create root-owned (not group/world-writable), regular, no-symlink single-grant JSON with exact fields {consent_ref,context_sha256,approver,approved_at,expires_at} in Stage131-specific protected approvals. Issue atomically with exclusive creation, durable fsync, never overwrite an existing ref.
4. KRC service UID988 can read but cannot write approval file/dir. The independent SQLite replay ledger is service-owned, private, durable and single-use. On missing grant, altered scope, expired/duplicate ref, bad ownership or audit mismatch: deny.
5. Completion evidence: original instruction digest, independent operator decision, local file metadata, scope hash, negative case matrix, UTC record, after-restart replay rejection; every step recorded without secrets. Only then can a specific live Science signer request be eligible for acceptance.

## Stage131 isolation
Grant directory must be distinct from Stage126: /etc/krc-stage131/approvals. Existing ConsentCustody128 defaults to /etc/krc-research-v2/approvals and therefore **must NOT be enabled unchanged in Stage131**. The Stage131 entrypoint remains explicitly signing-disabled until new dedicated approval path wiring and independent review are complete. No grant is generated by this document.
